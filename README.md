# 法规条款变更审阅 Web 应用

上传法规的**旧版**与**新版纯文本**，系统按段落顺序与字符串相似度自动生成
**可解释的条款对齐候选**，识别 **新增 / 删除 / 拆分 / 合并 / 改写** 五类变更
并给出置信度；审阅者可手动调整映射、记录审阅决定、按变更类型与状态筛选，
最终导出包含两版原文、变更类型与审阅决定的 **CSV / JSON** 结果文件。

技术栈：Python 3.11 + FastAPI + SQLite（标准库 sqlite3）+ 原生 JavaScript/CSS，
无前端构建步骤。

## 快速开始（Docker Compose）

```bash
docker compose up --build
```

启动后浏览器访问 <http://localhost:8000> 。

- 容器启动时自动在 `/data/review.db` 初始化数据库（建表幂等，可重复启动）；
- 数据库通过命名卷 `review-data` 持久化；
- 页面与 API 均使用 **8000** 端口。

停止并保留数据：`docker compose down`；连同数据卷一起删除：
`docker compose down -v`。

## 本地运行（不使用 Docker）

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 数据库默认写入 /data/review.db，本地运行建议指定当前目录：
export DB_PATH=./review.db
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

访问 <http://localhost:8000> 。

## 使用流程

1. **新建对齐**：填写批次名称，分别上传旧版、新版 `.txt` 文件
   （支持 UTF-8/UTF-8 BOM/GB18030 编码）。
2. 系统切分段落（优先按空行；无空行时按行并自动合并 CJK 折行），
   生成对齐候选。
3. **逐卡审阅**：
   - 查看左右两版原文、变更类型徽标、置信度条与「判定依据」；
   - 点击 **编辑映射**，勾选两侧段落重新建立映射（1 旧→多新为拆分、
     多旧→1 新为合并、只选一侧为新增/删除），可显式指定变更类型；
   - 记录审阅决定（认可 / 驳回 / 需修改）与备注后保存，卡片转为「已确认」。
4. **筛选**：按变更类型（新增/删除/拆分/合并/改写/无变更）和审阅状态
   （待审阅/已确认）过滤。
5. **导出**：CSV（带 UTF-8 BOM，Excel 可直接打开）或 JSON，
   内容包含两版原文、段落序号、变更类型、置信度、映射依据、审阅决定与备注。

## 对齐算法说明

1. **段落切分**：空行分段；无空行时按行切分，行尾/行首均为中日韩字符
   且上一行不以句末标点结束时合并折行，形如「第X条/数字编号」的行不合并。
2. **序列对齐**：对段落序列使用 `difflib.SequenceMatcher`，得到
   `equal / replace / delete / insert` 操作块；`equal` 即无变更。
3. **相似度**：中文单字 + 相邻双字、英文/数字小写词构成 token 集合计算
   Jaccard，与去空白小写字符串的字符序列相似度（SequenceMatcher）
   各取 50%；挂载判定时再加入“碎片 token 被源段包含的比例”，缓解短碎片
   改写后 Jaccard 偏低的问题。
4. **replace 块细化（保持段落顺序）**：
   - **非交叉锚点**：相似度矩阵上按分数降序贪心挑选 1:1 锚点（阈值 0.45），
     锚点两侧序号必须单调递增，杜绝远距离共享词汇造成的错配；
   - **空隙处理**：锚点之间的未配对段落，空隙内部按相似度非交叉配对
     （多对多重写）；未配对新段挂到旧段（1→N 拆分）、未配对旧段挂到
     新段（N→1 合并），挂接允许挂到相邻锚点段（顺序由“拆分挂前锚点、
     合并挂后锚点”及紧邻关系保证）；
   - **条号结构证据**：新版「第四条之一/第4-2条」等子条与同主号「第四条」
     紧邻出现时，是法规拆分的强信号，即便修订后文字变化较大也能挂上；
   - **链式闭合**：沿相邻已配对段落把多段合并/拆分串联完整（支持三段
     以上的合并）；挂不上的孤立段落按删除/新增处理；
   - 1:1：相似度 ≥ 0.92 判无变更，否则判改写。
5. **delete / insert 块**：默认判删除/新增，并在对面版本 ±4 段窗口内搜索
   最高相似度残留证据写入依据；相似度越低，删除/新增的置信度越高。
6. **置信度**：映射类（无变更/改写/拆分/合并）随原始相似度升高；
   删除/新增随相似度降低。结构奖励只用于“是否成边”的判定，边中保存的
   始终是原始相似度，置信度不会被条号奖励放大。每张卡片的「判定依据」
   可展开查看判定规则名、两两相似度等结构化证据。
7. **手动调整**：保存映射后服务端以新映射重新计算类型（也可显式指定）、
   置信度与依据，并标记「手动调整」；审阅者把已分配给其他候选的段落
   纳入新映射时，系统自动从原候选收回该段落（原候选两侧变空则删除、
   单侧变空则重判为删除/新增），保证两版每段都恰好被一条候选覆盖。

阈值集中在 `app/alignment.py` 顶部（`ANCHOR_THRESHOLD`、`SPLIT_ATTACH`、
`MERGE_ATTACH`、`CHAIN_ATTACH`、`MATCH_THRESHOLD` 等），可按文本风格调整。

## API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/batches` | 批次列表（含段落数、候选数、确认数） |
| POST | `/api/batches` | multipart 表单上传 `name`/`old_file`/`new_file`，建立对齐 |
| GET | `/api/batches/{id}` | 批次详情：两版段落 + 全部对齐候选（含原文） |
| DELETE | `/api/batches/{id}` | 删除批次（级联删除段落与候选） |
| POST | `/api/batches/{id}/realign` | 用两版文本重新生成候选（清空审阅记录） |
| PATCH | `/api/alignments/{id}` | 调整 `old_idx`/`new_idx`/`change_type`，或保存 `decision`/`decision_note`/`status` |
| GET | `/api/batches/{id}/export.csv` | 导出 CSV |
| GET | `/api/batches/{id}/export.json` | 导出 JSON |
| GET | `/healthz` | 健康检查 |

段落序号（`old_idx`/`new_idx`）均为 **1 基**整数数组，空数组表示该侧无映射。


## 导出字段（CSV）

对齐编号、变更类型（中文/英文）、置信度、审阅状态、审阅决定、审阅备注、
是否手动调整、旧/新版段落序号、旧/新版原文（多段以 `---` 分隔）。
JSON 导出额外包含逐条结构化判定依据（rationale.evidence）与批次元数据。
